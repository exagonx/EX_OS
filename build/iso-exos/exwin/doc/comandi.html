La riga di comando

La spiegazione di ogni comando e' nella macchina, non qui. help da' l'indice, help ls il blocco di un comando solo, help -t tutto di seguito. Il testo sta in /boot/help.txt: documentare un comando nuovo vuol dire aggiungere un blocco a quel file, senza ricompilare niente. Questa pagina e' la mappa, quello e' il manuale.

La sintassi

Piu' comandi su una riga

    uno ; due          esegui il secondo comunque
    uno && due         esegui il secondo solo se il primo e' riuscito
    uno || due         esegui il secondo solo se il primo e' fallito
    comando &          in secondo piano (vedi jobs, fg)

Dove va l'uscita

    comando > file      scrive sul file, buttando via cio' che c'era
    comando >> file     accoda in fondo
    comando < file      legge dal file invece che dalla tastiera
    comando 2> file     gli ERRORI sul file
    comando > f 2>&1    errori dove va l'uscita (l'ordine conta)
    uno | due          l'uscita del primo diventa l'ingresso del secondo

Virgolette e caratteri jolly

    cp "appunti di ieri.txt" /disco     tiene insieme cio' che ha spazi
    rm *.o                              il modello lo espande la shell
    cp "*.o" altrove                    fra virgolette NON si espande

Distingue maiuscole e minuscole. Su ext2 i nomi restano come li hai scritti; su FAT tornano in maiuscolo, e li' serve *.O. Se il modello non corrisponde a niente passa com'e', come su ogni shell POSIX: rm -f *.o in una directory gia' pulita non e' un errore.

Quello che NON c'e', detto: niente $VARIABILE sostituita dentro una riga, niente backtick, niente for ne' if. echo $PATH funziona perche' lo fa echo, non la shell.

gcc, g++, make, as, ld, ar, ranlib, nm, strip, objcopy, objdump, fbc: vengono dal CD degli strumenti, e stanno in Scrivere programmi.

L'ambiente

VariabileA che serve
PATHdove si cercano i programmi
HOMEla tua directory: cd senza argomenti ci torna, e i programmi ci tengono i loro dati sotto .app/
TERMche terminale e'

I valori iniziali stanno nella sezione [env] di /boot/kernel.cfg.

Dove sta cosa

    /bin        i programmi
    /dev        i driver: sono programmi anche loro
    /lib        le librerie condivise
    /boot       kernel.cfg, kernel.txt, help.txt, gli utenti
    /exwin      la scrivania: bin, lib, font, doc
    /doc        i documenti del progetto
    /cdrom      il CD, se c'e'
