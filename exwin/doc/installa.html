Installare EX-OS

La via breve: install e basta

Avvia dal CD e digita: 

    install

Senza argomenti l'installatore prende in mano tutto: mostra i dischi, chiede quanto dare al sistema, quanto all'area di scambio e se fare una terza partizione per i dati, partiziona, formatta, copia, scrive l'avvio e mette a posto kernel.cfg. Alla fine il disco parte da solo.

Le tre misure si chiedono in una schermata sola, con lo spazio non assegnato che si vede cambiare mentre le muovi. Chiederle una per volta vorrebbe dire far rispondere alla prima domanda senza sapere cosa resta per la terza.

Come si guida

    frecce      muoversi
    cifre       cambiare una misura
    Invio       confermare
    Esc         tornare indietro

L'installatore non usa la grafica, e non e' pigrizia. ExWin vuole il server a finestre, il server a finestre vuole una modalita' VESA che stage 2 imposta solo se la configurazione e' gia' scritta — cioe' se il sistema e' gia' installato. Un installatore che pretendesse la grafica non girerebbe nell'unico momento in cui serve.

I due programmi, e perche' sono due

ProgrammaDove staChe cosa fa
/bin/installanche sul floppy congelato: copia i file, installa l'avvio, fonde kernel.cfg. Basta a installare da un floppy, e basta.
/bin/cdinstallsolo sul CD tutto il resto, adesso e in futuro: le schermate, le partizioni, lo scambio.

La delega e' trasparente: chi digita install ha in mente l'installazione, non quale dei due programmi la faccia. install cerca cdinstall e gli cede il posto; senza CD non cambia niente. E cdinstall, per la copia, richiama install -diretto — che e' l'unico posto dove quel codice esiste.

Il motivo e' lo spazio, e si e' visto due volte in un giorno. Il floppy e' 1,44 MB che non crescono; il kernel cresce a ogni cosa che impara. Un installatore che continuasse ad arricchirsi la' dentro sarebbe il prossimo a togliere spazio all'unica cosa che sul floppy deve starci.

La via lunga, un passo per volta

Serve quando si vuole decidere tutto, o quando si installa su un disco che ha gia' altro sopra.

    disk                          quali dischi ci sono, e cosa non torna
    fdisk hd0                     creare le partizioni
    mkfs -t ext2 -L exos hd0p1    formattare quella di sistema
    mkswap hd0p2                  preparare l'area di scambio
    mount hd0p1 /disco            montarla dove si vuole
    install /disco                copiare il sistema li' dentro

Oppure, in un passaggio solo, la parte che riguarda un disco vergine: 

    install -prepara hd0

Le opzioni che contano

ComandoChe cosa fa
installla procedura guidata dal CD
install -prepara hd0prepara un disco: partizioni, formattazione, scambio, copia
install /discocopia il sistema su un volume gia' montato: riscrive tutto
install -a /discoaggiorna: copia solo cio' che sul supporto e' piu' nuovo
install -m /discosolo il sistema minimale
install -t /discotutti i componenti, senza chiedere
install -toolsgli strumenti di sviluppo, che vengono dal CD tools e non dal supporto d'avvio

Con degli argomenti non si apre nessuna schermata. Una procedura guidata in mezzo a un'automazione la blocca su una domanda che nessuno vedra': install -m /disco dentro uno script continua a funzionare identico.

Che cosa viene installato

Il sistema minimale, sempre: /bin, /boot, /lib, /dev, /drivers. E' cio' senza cui EX-OS non parte.

Tutto il resto e' un componente, e i componenti non sono un elenco scritto dentro l'installatore: qualunque altra directory di primo livello trovata sul supporto d'avvio viene mostrata e chiesta. Oggi sono /exwin (la scrivania, i caratteri e questa documentazione) e /doc; domani basta mettere una directory sul supporto.

Chi prepara un pacchetto non ha i sorgenti dell'installatore, ed e' la ragione per cui l'elenco non e' compilato dentro. E' la stessa ragione per cui l'elenco delle applicazioni grafiche e' un file di testo.

Il confine fra minimale e opzionale lo dice /boot/minimale.txt, che e' l'elenco dei file del floppy scritto leggendo il floppy. Un elenco scritto a mano nel sorgente sarebbe una seconda verita', e divergerebbe al primo programma aggiunto.

I driver non si copiano: si scelgono

L'installatore chiede a hwconfig quali driver servono su questa macchina e mette solo quelli, poi li dichiara nella sezione [modules] di kernel.cfg. Il driver di una scheda di rete che non c'e' sarebbe soltanto un file in piu' e una riga di errore all'avvio.

Aggiornare un sistema gia' installato

    install -a /disco

Fino alla versione 0.148 questa era la trappola peggiore. La copia saltava i file che esistevano gia': install su un sistema installato aggiornava i file nuovi e lasciava indietro tutti gli altri, kernel compreso. Il disco continuava ad avviare la versione vecchia mentre l'installatore stampava «Installazione completata». Adesso si riscrive sempre, e alla fine ogni file si rilegge per verificare che sul volume ci siano esattamente i byte che ci abbiamo scritto.

E la mappa dei settori del kernel vale finche' quel file non si sposta. Chi ricopia a mano kernel.bin o stage2 su un disco gia' installato deve rilanciare install, o il disco riparte con la versione di prima.

Dopo l'installazione

  1. reboot, e togli il CD;
  2. entra con login;
  3. se serve la rete: netdetect e poi dhcp — vedi La rete;
  4. exwin accende la scrivania — vedi La scrivania.
